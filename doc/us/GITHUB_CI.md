# GitHub Actions CI

The ncdc cross-interface fixtures reserve ports on both loopback addresses, retaining the conflicting listener until the client is ready. Allocation-only EADDRINUSE collisions choose a fresh pair with bounded retries; test failures are never retried. `integration.ncdc_ports` covers deterministic TCP/UDP collisions and cleanup.

The `Check status` workflow in `.github/workflows/build.yml` runs on GitHub-hosted `ubuntu-22.04`, `ubuntu-24.04` and `ubuntu-26.04`. Each job asserts four logical CPUs; available runner sizes depend on GitHub and repository visibility. Pushes to `main`, `fix`, the named historical release branches and the single `beta-0.2.7-beta-0.2.12-finish` branch run CI. Pull requests targeting `main` and manual dispatches also run; fork permission behavior is governed by repository settings. The workflow has read-only repository permissions and disables persisted checkout credentials. Use the workflow file for the authoritative branch list.

Two jobs run on each of those three images. C++ Debug, C++ Release and WebAdmin each run once per image. Each job checks that `nproc` equals 4 and then uses `nproc` workers. The C++ test step also runs `dependencies.audit`, which checks the direct shared libraries of the hub binaries, the exact WebAdmin lockfile and the security tests CMake always registers. That check does not add a job, a sanitizer matrix or a network scan. See [Dependencies](DEPENDENCIES.md). The same step runs `beta.baseline`, which checks the `beta-0.2.12` release string and the unchanged limits. See [Beta baseline](BETA.md). The C++ job builds and tests Debug and Release, including integration tests, after installing the toolchain, MariaDB, Apache and ncdc. The WebAdmin job builds the Release hub binary, then runs typecheck, the production build, Node tests, Chromium and the live C++ API integration with Node.js 22. Non-TLS bytes on a TLS port may end as EOF or one fatal alert record. A test client close accepts abrupt EOF or a completed unwrap(); the server still does not call SSL_shutdown().

Concurrency uses one group per workflow and ref, `dc24h-github-` plus the workflow name and ref, with `cancel-in-progress: false`. The C++ job has a 120-minute timeout and the WebAdmin job has a 60-minute timeout. Check each run under [GitHub Actions](https://github.com/adrianf87/dc24h.eu-high-starter/actions/workflows/build.yml) for actual results. CI completion is not awaited.

Push triggers CI; remote completion is not awaited.
