## Purpose and ownership

`include/dc24h/accounts/account.hpp` and `src/accounts/account.cpp` provide the independent C++20 `dc24h_accounts` library. An `accounts::Account` is checked, owning metadata for a persistent account. It is separate from `users::User`, which describes a public guest on one connection. Account IDs are neither ADC SIDs/CIDs nor `users::SessionId` values. No implicit binding or conversion exists.

The model supplies no credential field, password verifier, authentication result or permission grant. An `administrator` role in a detached value does not give a live session any authority. Existing guest ADC/ADCS login and permission sources are unchanged. Account persistence, application SQL migrations, uniqueness enforcement, registration, credential hashing/verification, authenticated account/session binding and administration remain future stages.

## Data contract

| Field | Contract |
| --- | --- |
| `AccountId` | Positive integer from 1 through 9223372036854775807; zero and values above signed BIGINT are rejected. Assigned by a future repository, never generated by this model. |
| `AccountName` | 1–64 **bytes**, already-NFC UTF-8. Reject malformed encoding, NUL, controls, format characters and Unicode separator characters, including nonbreaking spaces. No normalization, trimming or case folding. |
| `Role` | Exactly `registered`, `moderator` or `administrator`; keys are stable, case-sensitive EN/US data, not translated UI labels. Unknown enum values and keys are rejected. |
| `Status` | Exactly `disabled` or `active`; unknown enum values/keys are rejected. Import defaults to disabled and registered. |
| `Times` | Signed UTC Unix seconds in 0–253402300799 (1970-01-01 through 9999-12-31T23:59:59Z). Require `created_at <= updated_at`; optional `last_login_at` lies within that interval. Epoch zero is distinct from an absent login. |

Names retain exact bytes and case: `Alice` and `alice` are different values. Confusable characters are not merged. Names are not promised to be globally unique, safe SQL fragments, HTML or filenames. A future repository must deliberately choose matching uniqueness/collation policy and bind names as prepared parameters. Public protocol nickname restrictions are a separate adapter policy.

Times are explicit input; the library never reads the clock or assumes a timezone. Future timestamps within the range are structurally accepted because policy/clock validation belongs to the caller. Persisted date conversion belongs to a future SQL adapter. Updating metadata does not prove an actual login occurred.

## Construction and immutable candidates

`AccountData` is an untrusted owning import/snapshot structure. `Account::create` returns `std::variant<Account, AccountError>` after checking ID, enum values, times and name. Errors contain only enum categories (`invalid_id`, `invalid_name`, `invalid_role`, `invalid_status`, `invalid_times`); they do not echo input. No account/name/ID can be default-constructed through the checked value API.

```cpp
#include "dc24h/accounts/account.hpp"
using namespace dc24h::accounts;

AccountData input{42, "Żółw", Role::registered, Status::disabled,
                  Times{1700000000, 1700000000, std::nullopt}};
auto result = Account::create(input);
if (auto* account = std::get_if<Account>(&result)) {
    auto candidate = account->with_access(Role::registered, Status::active,
                                          1700000001);
    // Validate the result and commit it in a future trusted service/repository.
    // The original account and all connected users remain unchanged.
}
```

`with_name`, `with_access` and `with_last_login` return new checked candidates. They retain the account ID and creation time, require the supplied update time to be at least the existing update time, and preserve other metadata. Equal timestamps are allowed. `with_last_login` updates both the last-login and update timestamps; it is historical metadata only, including for disabled accounts. It does not authenticate, authorize or enable an account.

`snapshot()` produces an independent owning `AccountData`; mutations cannot affect the account. Copy assignment prepares a complete temporary before swapping, so allocation failure leaves the destination unchanged. Allocation failure propagates as `std::bad_alloc`; it is not reported as a validation error. String inputs are bounded before normalization/copying. Moved-from account/name values are invalid until assigned another value; `valid()` and candidate updates reject them. Accessors are read-only; the library performs no I/O and has no SQL, Network or ADC dependency.

These are detached values, not concurrent database transactions or version checks. A service must enforce authorization, uniqueness and optimistic concurrency when committing a candidate. Credentials must remain in a separate reviewed component and must not be added to public snapshots.

## Build and verification

The normal CMake build includes `dc24h_accounts`. Native consumers link that target. It uses the existing text/utf8proc dependencies and introduces no package dependency.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DDC24H_REQUIRE_INTEGRATION_TESTS=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
ctest --test-dir build -R '^accounts.model$' --output-on-failure
```

`accounts.model` checks checked-type construction, ID limits, byte-exact Unicode/NFC boundaries, control/separator rejection, stable role/status keys, unknown values, absent/epoch/range/order timestamps, snapshot ownership, candidate immutability, moved/self-assigned values and allocation failures during construction, export, updates and assignment. Existing full CTest suites, including real ncdc ADC/ADCS, MariaDB and Apache integrations, remain enabled. See [Testing](TESTING.md) and [Changelog](../../CHANGELOG.md) for actual results. Remote Check status is not awaited.

All GitHub Actions jobs continue to target the existing Ubuntu 24.04 self-hosted runner. Dependency preparation is an explicit administrator action; jobs run without sudo. See [CI setup](CI_DEBIAN13.md).
