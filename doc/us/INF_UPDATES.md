## Incremental contract

The [ADC INF specification](https://adc.sourceforge.io/ADC.html#_inf) defines updates to supplied fields, preservation of omitted fields and cancellation by a bare field name. `adc::InfUpdates` implements this for ready, public guests. It borrows SessionManager in the single reactor thread and owns no socket, persistent registry, database, clock or credential. Callers supply the ClientSession belonging to the local SessionId. Initial identification stays in UserLogin and full initial snapshots stay in UserList.

The public output is now an incremental BINF, rather than a full public snapshot plus cancellations. Fields follow the validated input's order. Supplied known public values are copied from the validated candidate, including normalized peer addresses, never from untrusted raw values. Explicit unchanged known values are still echoed for compatibility. A supplied cancellation is forwarded as a bare name only if the old snapshot retained that field. Omitted fields remain in metadata/profile and are not included in the delta. Unknown fields, never-advertised cancellations and empty input produce no public field; an entirely empty/unknown-only delta is not relayed. PID is forbidden on updates and is never retained/distributed.

Later newcomers still receive the complete current public ClientInfo, not a history of deltas. This preserves ADC-only metadata (addresses, declared connection speeds, hub counts and similar fields) in addition to the generic User profile. Zero numeric declarations remain values; bare SS/SF/SL remove their optional values. Client declarations are untrusted metadata, not verified share content or privileges.

## Staging and commit

`InfUpdates::apply(id, client, parsed_message, now)` requires an existing ready Session and protocol NORMAL. It checks that projecting the current ClientInfo yields the same registered User identity/profile. This detects a mismatched peer or an adapter that independently changed model-covered metadata. It is not an independent authentication of the caller's transport ID or a comparison against a second stored copy of ADC-only fields.

ClientSession exposes no mutable metadata. Private friend-only prepare_update validates a candidate using the existing InfValidator without changing protocol metadata. It enforces BINF/source SID, required identity, immutable CID, no PID, unique fields, character/UTF-8/NFC and size rules, numeric/feature constraints, peer address checks and privilege-claim limits. The parser remains responsible for frame/argument syntax; non-NFC/invalid syntax frames can be discarded there before this module. Normal-state INF has no additional ADC state transition to commit.

The complete candidate is projected to a bounded User. The public delta is built and serialized for validity before any managed change. SessionManager then transactionally applies the User/profile and nickname index with unchanged SID/CID and monotonic time. Only after that succeeds does a nonthrowing move replace ClientInfo. Returning the owned result is also nonthrowing. Typed rejection or allocation failure before commit preserves ClientInfo, User/profile, public keys and nickname ownership together, including when a multi-field update has an earlier valid field followed by an invalid one. An unrelated user's reservation is preserved. Supplied time is used without hidden clock reads.

`InfUpdateResult` contains AppliedInfUpdate with an optional owned public message, or InfUpdateFailure. Failure distinguishes ClientSessionError, RegistryError, SessionError and internal identity_mismatch/invalid_public_user/invalid_output. Existing ADC status mappings remain: duplicate nickname 222, duplicate CID 224, invalid nick 221, invalid peer address 246, other invalid required INF data generally 243, state 244 and internal/model invariants 210. The status text uses existing fixed messages and never client payloads.

Standalone ClientSession::observe still supports its existing protocol-only INF composition tests. A live adapter paired with SessionManager must use InfUpdates for ready-state mutation; independently calling observe on metadata and then changing the User loses the joint transaction and can cause a detected mismatch. Accepted/identified/welcome-pending/closing/closed sessions cannot use this updater.

## Live distribution and limits

LoginHub routes ready-state INF to InfUpdates before the generic observe path. Existing early nickname collision checks remain. After success it relays the owned sanitized delta to the sender and all admitted nonclosing peers, including identified recipients whose welcome is queued. FIFO keeps their own-INF delimiter before subsequent updates. Initial lists use the committed complete metadata, so a later newcomer and existing clients converge after cancellations and rename. Updates do not emit another login/readiness event.

bad_alloc during the apply operation is caught at LoginHub's boundary and forces immediate internal-error closure without allocating another status frame. The failed update is not published and the old identity/profile stays reserved until cleanup. Existing per-client/global queue caps, pinned TLS front, output deadlines and disconnect/IQUI cleanup continue to apply. Fanout happens after the model commit: a slow recipient can be disconnected when its queue fills; there is no atomic network-wide delivery/rollback or full-system OOM guarantee. Postcommit fanout allocations are outside the apply guard.

Temporary work is bounded by the existing 16 KiB frame, 128 parameters and 4096-byte retained ClientInfo limits, plus bounded User/profile/index data. The updater allocates candidate/projection/delta storage before commit. No new limit setting, dependency, SQL migration, API JSON field, WebAdmin function or runtime translation key is needed. EN/US UTF-8 and existing languages/us/languages/pl catalogs remain. Accounts, roles, persistence and chat/search/transfer dispatch remain future work.

## Verification

`users.inf_updates` checks requested-field deltas, normalized IPs, Unicode rename/description, zero values, cancellations, preservation of omitted fields, known unchanged echoes, unknown/empty suppression and unchanged owning snapshots. Typed failures cover invalid multi-field values, nickname collision, required-name removal, PID, privilege/IP/feature/text/duplicate-field errors, source spoof, backwards time, missing/pending/closing models and stale adapter metadata. A scoped C++ allocation campaign retries every allocation in validation/projection/delta/index staging and confirms both models/indexes remain unchanged on failure, with another user preserved. C allocator/OS fault injection is not claimed.

`users.inf_updates.process` verifies equal incremental fanout to mixed ADC/ADCS peers, raw-private-field filtering, normalized values, explicit cancellations, unknown-only suppression, a later newcomer's full snapshot, no invalid-update broadcast before terminal rejection and same-CID reconnect. Both transport directions run. Real ncdc changes its description live through this path over ADC and ADCS; its optional simultaneously supplied HN declaration is forwarded, without unrelated full-profile fields. Existing registry/list tests now assert incremental semantics while retaining user-list convergence and stable CID routing. See [TESTING.md](TESTING.md) for local regression results and limits.
