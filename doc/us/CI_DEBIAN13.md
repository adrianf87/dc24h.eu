# Debian 13 custom-runner CI

`.github/workflows/proxmox-debian13.yml` runs automatically on pushes to `main` and `alpha-*` branches and supports `workflow_dispatch`. It does not run fork pull-request code on the custom runner. The existing `proxmox-vm100` concurrency group serializes VM owners without canceling an active run.

The existing start job requires VM 100 to be stopped, powers it on through its restricted SSH command, then waits for running status. Tests use the existing labels `[self-hosted, Linux, X64, ci-controller]`. The test job verifies `/etc/os-release` is Debian 13 and prints CMake, C++ and ncdc versions. The matrix runs **Debug and Release sequentially** (`max-parallel: 1`, `fail-fast: false`) with separate `build-debian13-Debug` / `build-debian13-Release` directories. Each entry configures `DC24H_REQUIRE_INTEGRATION_TESTS=ON`, builds C++20 with two workers and runs all registered CTest suites, including real ncdc, MariaDB and Apache HTTPS. There is no fixed historical test-count gate.

The existing shutdown job runs after the entire matrix, including test failure, when VM startup succeeded. The same strict SSH host-key validation, secret names, VM ownership precondition, timeouts and power commands are preserved. If the VM is already running, startup fails instead of claiming ownership or shutting it down. Repository administrators provision the runner and the existing `PVE_VM100_SSH_KEY` / `PVE_VM100_KNOWN_HOSTS` secrets; no secret values are stored in the repository.

Provision CMake >=3.22, a C++20 compiler, Python >=3.8, utf8proc/OpenSSL/libgcrypt/MariaDB development libraries, OpenSSL CLI, ncdc, MariaDB server/client installation tools and Apache2 before running. Missing required integration tools fail CMake configuration. The C++ test job does not install or require a system Node/npm package. The Ubuntu WebAdmin job still uses **Node 22** through `actions/setup-node@v5`.

All three checkout steps now use `actions/checkout@v6`; the existing custom-runner `persist-credentials: false` is retained. [Checkout v6](https://github.com/actions/checkout/blob/v6/action.yml) and [setup-node v5](https://github.com/actions/setup-node/blob/v5/action.yml) declare the action runtime as Node 24, supplied by a compatible Actions Runner. This runtime is separate from `node-version: 22` used to build WebAdmin. No apt installation of Node 24 or warning-suppression environment flag is needed. The configured runner must support Node 24 actions; keep its runner installation updated.

Validate workflows locally with `actionlint`; `.github/actionlint.yaml` declares `ci-controller` as a custom label. Workflow publication starts the push jobs automatically. Their URLs/status may be reported immediately, without waiting for completion or claiming a remote pass. Local regression results and remote runner results are distinct.
