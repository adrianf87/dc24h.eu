# CI w GitHub Actions

Testy ncdc z konfliktem interfejsów rezerwują porty na obu adresach loopback i zachowują drugi nasłuch do gotowości klienta. Wyłącznie kolizja EADDRINUSE przy przydziale wybiera nową parę w ograniczonej pętli; sam test nie jest ponawiany. `integration.ncdc_ports` sprawdza deterministyczne kolizje TCP/UDP i sprzątanie.

Workflow `Check status` z `.github/workflows/build.yml` działa na runnerach GitHub-hosted `ubuntu-22.04`, `ubuntu-24.04` i `ubuntu-26.04`. Każde zadanie wymaga czterech logicznych CPU; wielkość dostępnych runnerów zależy od GitHub i widoczności repozytorium. Push do `main`, `fix`, wymienionych gałęzi historycznych i jednej `beta-0.2.7-beta-0.2.12-finish` uruchamia CI. Uruchamiają je także PR do `main` i ręczne wywołanie; uprawnienia forków zależą od ustawień repozytorium. Workflow ma uprawnienia tylko do odczytu i nie zachowuje poświadczeń checkout. Obowiązującą listę gałęzi zawiera plik workflow.

Dwa zadania działają na każdym z tych trzech obrazów. C++ Debug, C++ Release i WebAdmin uruchamiają się raz na obraz. Każde zadanie sprawdza, że `nproc` równa się 4, i potem używa workerów `nproc`. Krok testów C++ uruchamia też `dependencies.audit`, który sprawdza bezpośrednie biblioteki dzielone plików huba, dokładny lockfile WebAdmin i testy bezpieczeństwa rejestrowane przez CMake zawsze. To sprawdzenie nie dodaje zadania, macierzy sanitizerów ani skanu sieci. Zobacz [Zależności](DEPENDENCIES.md). Ten sam krok uruchamia `beta.baseline`, który sprawdza napis wydania `beta-0.2.12` i niezmienione limity. Zobacz [Linia beta](BETA.md). Zadanie C++ buduje i testuje Debug oraz Release, łącznie z testami integracyjnymi, po instalacji narzędzi, MariaDB, Apache i ncdc. Zadanie WebAdmin buduje binarny hub Release, a potem sprawdza typy, buduje wersję produkcyjną, uruchamia testy Node, Chromium i integrację żywego API C++ na Node.js 22. Niepoprawny tekst na porcie TLS może skończyć się EOF albo jednym rekordem fatal alert. Zamknięcie klienta akceptuje nagłe EOF albo zakończone unwrap(); serwer nadal nie wywołuje SSL_shutdown().

Jedna grupa współbieżności na workflow i ref, `dc24h-github-` plus nazwa workflow i ref, ma `cancel-in-progress: false`. Zadanie C++ ma limit 120 minut, a WebAdmin 60 minut. Faktyczne wyniki każdego przebiegu są dostępne w [GitHub Actions](https://github.com/adrianf87/dc24h.eu-high-starter/actions/workflows/build.yml). Nie czekamy na zakończenie CI.

Push uruchamia CI; nie czekamy na jego zakończenie.
