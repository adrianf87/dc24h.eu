# CI w GitHub Actions

Testy ncdc z konfliktem interfejsów rezerwują porty na obu adresach loopback i zachowują drugi nasłuch do gotowości klienta. Wyłącznie kolizja EADDRINUSE przy przydziale wybiera nową parę w ograniczonej pętli; sam test nie jest ponawiany. `integration.ncdc_ports` sprawdza deterministyczne kolizje TCP/UDP i sprzątanie.

Workflow `Check status` z `.github/workflows/build.yml` działa na runnerach GitHub-hosted `ubuntu-22.04`, `ubuntu-24.04` i `ubuntu-26.04`. Etap I beta-0.3.3 usuwa założenie o dokładnie czterech logicznych CPU; zadania używają dostępnego `nproc`. Etap II beta-0.3.7 dodaje testy TOTP, anty-replay i sesji MFA do testów Node WebAdmin. Etap III beta-0.3.10 dodaje testy szyfrów i nagłówków HTTPS, ograniczenia izolacji i testy prywatnego pilotażu z pięcioma stałymi trasami. Etap IV beta-0.3.12 dodaje ograniczone testy obciążenia/awarii, sprawdzone rekordy audytu i test CTest warunków wydania. Push do `main`, gałęzi historycznych i `beta-0.3.1-12-full` uruchamia CI, podobnie PR do `main` i ręczne wywołanie. Workflow ma uprawnienia tylko do odczytu i nie zachowuje poświadczeń checkout. Obowiązującą listę gałęzi zawiera plik workflow.

Dwa zadania działają na każdym z trzech obrazów. C++ Debug, C++ Release i WebAdmin uruchamiają się raz na obraz, z workerami `nproc`. Krok C++ wykonuje `dependencies.audit` dla bibliotek, lockfile i testów bezpieczeństwa, a także `beta.baseline` dla `beta-0.3.12`. Zobacz [Zależności](DEPENDENCIES.md) oraz [Linię beta](BETA.md). WebAdmin po `npm ci` sprawdza ostrzeżenia wysokiego ryzyka dla zależności produkcyjnych, buduje i testuje TypeScript/Node/Chromium oraz integrację C++ na Node.js 22. Dodatkowe dwie kompilacje Ubuntu 24.04 uruchamiają wybrane testy C++ z ASan i UBSan; ich wyniki warunkują istniejący wymagany check. Nie są to testy ThreadSanitizer ani fuzzing sterowany pokryciem. Niepoprawny tekst na porcie TLS może skończyć się EOF albo jednym rekordem fatal alert; serwer nadal nie wywołuje SSL_shutdown().

Jedna grupa współbieżności na workflow i ref, `dc24h-github-` plus nazwa workflow i ref, ma `cancel-in-progress: false`. Zadanie C++ ma limit 120 minut, a WebAdmin 60 minut. **Bieżące** wyniki repozytorium Twilight są dostępne w [GitHub Actions](https://github.com/adrianf87/dc24h.eu-twilight/actions/workflows/build.yml); historyczne przebiegi źródłowego projektu pozostają wyłącznie dowodem dla dawnego SHA. Nie czekamy na zakończenie CI.

Push uruchamia CI; nie czekamy na jego zakończenie.
